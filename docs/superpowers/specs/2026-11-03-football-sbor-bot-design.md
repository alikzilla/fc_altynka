# Сбор на футбол: Telegram-бот + мини-апп (MVP)

Дата: 2026-11-03 · Статус: черновик на согласование

## 1. Зачем

Компания друзей (~50 человек в Telegram-группе) регулярно играет в футбол. Сейчас всё держится на сообщениях в группе:
каждый, кто хочет играть, копирует список, дописывает своё имя и отправляет новым сообщением; при переполнении пишет себя
в резерв; при сливе кто-то вручную переносит первого из резерва и тегает его. После игры оплативший поле публикует список
и тегает всех, кто должен скинуть деньги.

Процесс работает, но группа превращается в базар: одинаковые сообщения со списками, теги, повторы. Важное тонет.

**Цель MVP:** убрать шум и собрать весь цикл «сбор → игра назначена → составы → деньги» в одном месте, чтобы это
выглядело аккуратно. В группе живёт одно сообщение со списком, которое бот обновляет сам; записаться можно одной кнопкой
прямо под ним.

## 2. Цели, не цели, анти-цели

**Цели**
- Записаться или слиться — одно нажатие в группе, без открытия мини-аппа.
- Список, резерв и перенос из резерва ведутся автоматически, с уведомлением того, кого перенесли.
- Организатор назначает время и длительность после бронирования поля; лимит пересчитывается сам.
- Составы делятся по уровню игроков (1–10) и публикуются одним красивым сообщением.
- Счёт после игры: кто платил арендатору, сумма, допрасходы, кто должен; оплаты отмечаются кнопкой.

**Не цели (в MVP не делаем)**
- Ничего во время игры: счёт матчей, таймер, ротация «кто сидит», голы, пасы.
- Оценки, MVP, рейтинги, ачивки, лента, статистика, карточки и аватарки из артефакта.
- Переводы денег через бота, интеграция с Kaspi. Бот только показывает, сколько и кому.
- Автоматические напоминания по расписанию.
- Интерфейс для нескольких групп (данные к этому готовы, см. §9).

**Анти-цели (провал, даже если всё технически работает)**
- Записаться через бота сложнее, чем вписать имя в список.
- Бот шумит в группе больше или так же, как сейчас.
- Организатор тратит на сбор больше времени, чем раньше.

## 3. Роли

| Действие | Игрок | Организатор | Админ |
|---|---|---|---|
| «Иду» / «Не иду», «+ Друг», смотреть список, составы, счёт, «Я скинул» | ✅ | ✅ | ✅ |
| Создать сбор, назначить время/часы/поле, отменить сбор | | ✅ | ✅ |
| Перевести из резерва в основу, убрать из списка (в т.ч. гостя) | | ✅ | ✅ |
| Поделить команды, менять игроков, опубликовать составы | | ✅ | ✅ |
| Выставить и править счёт, отметить оплату вручную, «Напомнить должникам» | | ✅ | ✅ |
| Видеть уровни игроков | | ✅ | ✅ |
| Выставлять уровни 1–10, назначать/снимать организаторов | | | ✅ |

- Админ один — владелец проекта. Его Telegram ID задаётся секретом при деплое.
- Игроком становишься автоматически при первом нажатии «Иду» (или открытии мини-аппа). Имя и аватарка из Telegram,
  регистрации нет. Новичок получает уровень 5.
- Игроки никогда не видят уровни — ни свои, ни чужие, ни суммы по командам.
- Любой организатор может управлять любым сбором.

## 4. Жизненный цикл сбора

Статусы: **Сбор** → **Игра назначена** → **Счёт** → **Закрыт**. Из «Сбора» и «Игры назначена» можно уйти в **Отменён**.
Составы — необязательный шаг внутри «Игра назначена».

### 4.1 Создание
Организатор в мини-аппе: «Новый сбор» → дата (обязательно), комментарий (необязательно). Время и длительность пусты.
Бот публикует сообщение сбора в группе (§5) и закрепляет его, если у бота есть права. Одновременно может быть
несколько активных сборов (например, на субботу и воскресенье), у каждого своё сообщение.

### 4.2 Запись, очередь, резерв
- Каждая запись (игрок или гость) получает порядковый номер по времени нажатия. Порядок однозначен даже при
  одновременных нажатиях.
- **Лимит:** по умолчанию 10. После назначения игры: 1 час → 10, 2 часа → 15.
- **Основа** = первые `лимит` записей по порядку + вручную переведённые организатором. **Резерв** = остальные по порядку.
- **«Иду»:** встаёшь в конец очереди. Если уже записан — бот отвечает всплывашкой «Ты уже в списке, №7» (или «в резерве, №2»).
- **«Не иду» (слиться):** запись удаляется. Если ты был в основе, первый из резерва переходит в основу, бот его отмечает (§5).
  Если в течение 2 минут снова нажать «Иду», возвращаешься на прежнее место (защита от случайного нажатия).
- **Ручной перевод из резерва:** организатор выбирает конкретного человека → тот попадает в основу, лимит этого сбора
  растёт на 1. Когда кто-то из основы сливается, его место занимает первый из резерва, как обычно.
- **Убрать из списка:** организатор может удалить любую запись; правила переноса те же.
- **2 часа → 1 час:** лимит обратно 10; лишние из основы (последние по порядку, кроме вручную переведённых) уходят
  в начало резерва в том же порядке.

### 4.3 Гости
- Кнопка «+ Друг» под сообщением сбора открывает мини-апп на форме: имя друга.
- Гость встаёт в очередь по тем же правилам, что и игрок. В списке: «Ержан (друг: Тимур)» — имена не склоняем.
- Убрать гостя может тот, кто его записал, или организатор. Если пригласивший слился, гость остаётся.
- Уровень гостя по умолчанию 5; организатор может поправить его на этапе составов (только для этого сбора).

### 4.4 Назначение игры
После бронирования организатор в мини-аппе: «Назначить игру» → время начала, длительность (1 ч / 2 ч), поле (текст).
Лимит пересчитывается (§4.2), сообщение сбора обновляется, бот отправляет короткое уведомление (§5). Время, длительность
и поле можно поменять позже — с тем же пересчётом и уведомлением.

### 4.5 Отмена
Организатор: «Отменить сбор» (двухшаговое подтверждение). Сообщение сбора получает пометку «Отменён», кнопки исчезают,
бот отправляет короткое уведомление.

### 4.6 Составы
- Количество команд: меньше 15 человек в основе — 2, от 15 — 3. Организатор может переключить 2/3.
- Размеры команд равны или отличаются на 1.
- «Поделить» раскладывает основу так, чтобы суммы уровней команд отличались минимально. «Ещё вариант» даёт другой
  расклад не хуже лучшего более чем на 1 очко. Это алгоритм в мини-аппе, не внешний ИИ.
- Ручная правка: нажать двух игроков из разных команд — они меняются местами; если команды неравны по размеру,
  можно перенести одного игрока.
- Команды: 🔴 Красные, 🔵 Синие, 🟡 Жёлтые (третья — только при 3 командах).
- «Опубликовать» → сообщение составов в группе (§5). Повторная публикация после правок редактирует то же сообщение.
- Если после публикации кто-то слился или добавился, мини-апп показывает организатору, что составы устарели.

### 4.7 Счёт и оплата
Организатор после игры: «Выставить счёт».
1. **Кто заплатил арендатору:** по умолчанию организатор, можно выбрать любого игрока.
2. **Номер Kaspi получателя:** берётся из его профиля; если пусто, организатор вписывает, номер сохраняется в профиль получателя.
3. **Сумма:** аренда поля + строки допрасходов («Вода — 1 500 ₸»). Всё делится поровну.
4. **Кто платит:** по умолчанию вся основа; организатор может снять отметку с не пришедших или добавить кого-то.
   Доля гостя висит на пригласившем («Тимур — 4 000 ₸, за себя и друга»).
5. **Доля** = итог / число долей, округлённая вверх до 50 ₸. Излишек от округления остаётся получателю.
6. Получатель денег сразу отмечен как оплативший.

После публикации: игрок жмёт «Я скинул» (в группе или в мини-аппе) — отметка появляется сразу. Получатель и организаторы
видят в мини-аппе, кто отметился, и могут снять отметку или отметить человека вручную. «Напомнить должникам» (кнопка
организатора) — одно сообщение в группе с отметками тех, кто не скинул.

Счёт можно править после публикации. Если доля выросла, а человек уже отметился, он видит «доплатить N ₸».
С момента выставления счёта список сбора заморожен. Когда все оплатили (или организатор нажал «Закрыть»), сбор закрыт.

**Kaspi.** Публичной ссылки, открывающей перевод с заполненными номером и суммой, нет. Кнопка «Перевести» копирует номер
получателя и пытается открыть приложение Kaspi; сумма показана крупно и копируется отдельно. Разработчик проверяет
на реальных iOS и Android, открывается ли Kaspi по ссылке; если надёжного способа нет — только копирование.

## 5. Сообщения бота в группе

Главный принцип: **редактировать, а не слать новое**. Новое сообщение — только когда конкретным людям нужно
уведомление (правки в Telegram не уведомляют).

| Сообщение | Когда | Дальше |
|---|---|---|
| **Сбор** | создан сбор | редактируется при каждом изменении списка, времени, статуса |
| Короткое уведомление (ответом на сбор) | перенос из резерва; игра назначена или изменена; отмена | новое, одно на событие; если перенесли сразу пятерых — одно сообщение со всеми |
| **Составы** (ответом на сбор) | «Опубликовать» | редактируется при повторной публикации |
| **Счёт** (ответом на сбор) | «Выставить счёт» | редактируется при оплатах и правках |
| Напоминание должникам | кнопка организатора | новое |

Итого за сбор примерно 3 «больших» сообщения и несколько однострочных уведомлений — против десятков копий списка сейчас.

**Сообщение сбора** содержит: дату, статус («Время уточняется» / «21:00–23:00, поле X»), пронумерованную основу,
резерв, гостей с пометкой, счётчики. Кнопки: «✅ Иду», «❌ Не иду», «➕ Друг», «📱 Открыть».

**Сообщение счёта:** «С каждого по 2 000 ₸ → Азамат, Kaspi +7 7xx…», оплатившие с галочкой, должники списком.
Кнопки: «📋 Номер Kaspi» (копирует номер; через `copy_text`, если работает в группах, иначе — открывает мини-апп),
«✅ Я скинул».

**Отметки** людей без username — через ссылку на пользователя по ID, чтобы уведомление пришло всем.

## 6. Мини-апп: экраны

Язык — русский. Цвета берутся из темы Telegram (светлая/тёмная); визуальный стиль — из артефакта пацанов:
карточки, один зелёный акцент, шрифт Onest, крупные кнопки.

1. **Главная** — активные сборы карточками (дата, статус, «идут 9/10, резерв 2», мой статус), ниже несколько прошедших.
2. **Сбор** — шапка (дата, время, поле, статус), основа, резерв, мои кнопки (Иду / Не иду / + Друг).
   Организатору: «Назначить игру», перевод из резерва, удаление, «Отменить». Вкладки: Список · Составы · Счёт.
3. **Составы** — для игроков: просмотр опубликованных команд. Для организаторов: поделить, ещё вариант, 2/3 команды,
   обмен, уровни гостей, опубликовать.
4. **Счёт** — игроку: сколько, кому, «Перевести», «Я скинул». Организатору: создание и правка счёта, кто оплатил,
   ручные отметки, «Напомнить должникам», «Закрыть».
5. **Игроки** (организаторы и админ) — список с уровнями. Админ правит уровень 1–10, роль, отображаемое имя.
6. **Профиль** — отображаемое имя (по умолчанию из Telegram), номер Kaspi.

Открывается мини-апп: кнопкой «📱 Открыть» и «➕ Друг» в сообщении сбора (прямая ссылка `t.me/<бот>/<апп>?startapp=…`,
т.к. web_app-кнопки в группах Telegram не разрешает) и кнопкой меню в личке с ботом.
Доступ только участникам привязанной группы.

## 7. Технические решения (приняты)

- **Язык:** TypeScript везде.
- **Хостинг:** Cloudflare. Один Worker: вебхук бота, API мини-аппа и раздача статики мини-аппа (Workers Static Assets).
- **База:** Cloudflare D1 (SQLite), доступ через Drizzle ORM.
- **Бот:** grammY на вебхуке (`webhookCallback` для Cloudflare), вебхук защищён секретным токеном.
- **API:** Hono.
- **Мини-апп:** React + Vite.
- **Авторизация:** подпись `initData` от Telegram проверяется на сервере ключом бота; устаревшие данные (старше 24 ч)
  отклоняются. Логинов и паролей нет.
- **Привязка группы:** бота добавляют в группу, админ пишет в ней `/bind`; группа становится сообществом.
  В MVP бот обслуживает одну привязанную группу.
- **Часовой пояс:** Asia/Almaty для всех дат и сравнений «сегодня/прошло».
- **Доменная логика** (очередь и резерв, лимиты, деление команд, расчёт счёта) — отдельный модуль чистых функций
  без зависимостей от Telegram и базы, покрытый юнит-тестами.

## 8. Ограничения Telegram, которые надо соблюдать

- Бот может слать/редактировать в одной группе примерно 20 сообщений в минуту. При всплеске нажатий правки сообщения
  сбора склеиваются: не чаще одной правки в ~3 секунды, всегда с актуальным состоянием из базы; ответ 429 обрабатывается
  по `retry_after`. Требование: сообщение отражает реальный список не позже чем через несколько секунд и не теряет
  последнее состояние. Механизм (например, Durable Object с alarm на каждое сообщение) — на выбор разработчика.
- На нажатие inline-кнопки бот отвечает всплывашкой сразу, не дожидаясь правки сообщения.
- Боту в группе не нужен доступ к сообщениям (privacy mode включён). Для закрепления нужны права админа группы;
  без них бот просто не закрепляет.

## 9. Данные (набросок)

Данные с первого дня привязаны к сообществу (Telegram-группе), чтобы позже не переделывать базу.

- `communities` — id, tg_chat_id, название.
- `users` — id, tg_id, имя/фамилия/username из Telegram, отображаемое имя, номер Kaspi.
- `memberships` — сообщество, пользователь, роль (admin / organizer / player), уровень 1–10 (по умолчанию 5).
- `events` — сообщество, дата, время начала, длительность (1/2), поле, комментарий, статус, базовый лимит,
  id сообщений в группе (сбор, составы, счёт), кто создал.
- `signups` — сбор, пользователь или гость (имя гостя + кто пригласил), порядковый номер, «переведён вручную»,
  время удаления (для 2-минутного возврата), уровень гостя.
- `teams` — сбор, команда (цвет), запись.
- `bills` — сбор, получатель, аренда, допрасходы, доля, статус.
- `bill_lines` — счёт, плательщик, число долей (1 + гости), сумма, отметка оплаты и кто её поставил.

Точная схема — на разработчике.

## 10. Что взято из артефакта пацанов

**Берём:** визуальный стиль (карточки, зелёный акцент, Onest); логику «основа = первые N, остальные — резерв»;
подход к делению команд (перебор вариантов с обменами и минимизацией разницы); двухшаговые подтверждения опасных действий;
копирование текста с запасным вариантом.

**Учитываем ошибки артефакта:** данные только в браузере (у нас — общая база); дата по UTC (у нас — Алматы);
захардкоженные склонения (у нас — нормальная плюрализация).

**Не берём сейчас:** всё, что во время и после игры кроме денег (§2).

## 13. Решения, принятые без явного согласования (проверить)

1. Возврат на прежнее место, если снова нажал «Иду» в течение 2 минут после «Не иду».
2. Ручной перевод из резерва добавляет место сверх лимита.
3. 2 ч → 1 ч: лишние из основы возвращаются в начало резерва.
