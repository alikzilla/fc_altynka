# Страница матча: вкладка «Игры», жеребьёвка монетой, редактор составов и ассисты

Дата: 2026-11-10. Статус: согласовано в брейнсторме, ждёт плана.

## Зачем

Организатор жалуется на две вкладки страницы матча — «Игры» и «Составы»: «там много проблем UI и UX».

1. **«Игры» плоская.** В материал (синий) завёрнута только текущая игра. Таблица — серая карточка, «Последние игры» и «Бомбардиры» — голые списки без поверхности. Вкладка выпадает из системы материалов Airofit, на которой построен профиль (пользователь называл её «liquid glass»; имеется в виду именно Airofit из DESIGN.md — непрозрачные цветные поверхности со светящимся краем, без стекла и блюра).
2. **Первую пару никто не видит.** При «Начать матч» сервер молча выбирает пару (`chooseFirstPair`), и вкладка «Игры» просто появляется с готовым «A — B». Пользователь хочет интерактивную монету, которая подлетает и показывает результат.
3. **Редактор «Составы» перегружен.** До первого игрока шесть элементов (статус, 2/3 команды, «Цвета команд», «Другой вариант», «Отменить», подсказка). «Обменять» на каждой строке — 18 одинаковых кнопок. «Другой вариант» и смена числа команд дополнительно спрашивают подтверждение, хотя есть отмена. Баланс спрятан в сером тексте. Старт — четыре шага: опубликовать → «Начать матч» → шторка подтверждения цветов → результат.
4. **Ассисты не записываются.** В профиле ячейка «Ассисты» всегда показывает «—».

## Цели

- Вкладка «Игры» целиком на материалах Airofit: текущая игра — синий материал, остальные блоки — графитовые карточки.
- Жеребьёвка монетой в стиле 200 тенге, которая отвечает на правильный вопрос: при трёх командах — кто отдыхает первым, при двух — кто начинает с мячом.
- Редактор составов: одна карточка баланса, мгновенное «Перемешать», обмен двумя тапами, цвет формы из карточки команды, одна меняющаяся главная кнопка, старт в одной шторке.
- Вид составов для игрока — те же карточки без редактирования.
- Ассист у каждого гола: ввод в шторке результата, показ в истории игр, подсчёт в профиле.

## Не цели

- Вкладки «Участники» и «Оплата», плоская карточка матча над вкладками.
- Сообщения бота в Telegram (составы, протокол) — не меняются.
- Новые достижения на ассистах.
- Таймер игры: «ориентир 6 минут» убирается, вместо него ничего не появляется.

## Анти-цели

- Стекло, блюр, «свечения» вокруг элементов. Только существующие материалы `material-blue` / `material-graphite` и токены из `app.css`.
- Перебрасывание монеты как способ переиграть жребий. Результат решает сервер один раз.
- Монета как копия реальных денег: без государственного герба и надписи «QAZAQSTAN RESPÝBLIKASY».
- Цвет как единственный носитель смысла: цвет команды всегда подписан названием.

## Визуальные источники

Мокапы из брейнсторма лежат локально (каталог `.superpowers/` в git не попадает):
`.superpowers/brainstorm/66991-1794255117/content/` — финальные версии `games-and-coin-v5.html` (вкладка «Игры» + монета), `teams-editor-v6.html` (редактор + шторка старта), `assists-v2.html` (вариант A). Ниже всё описано словами; при расхождении текст главнее.

## 1. Вкладка «Игры»

### Пока матч идёт

Сверху вниз, отступы между блоками как сейчас (стек с зазором 16 px):

**Текущая игра — карточка `material-blue`.**
- Строка мета: «Игра N». Без «6 минут» и без «ориентир».
- Противостояние в три колонки: слева и справа — круглый «диск формы» в цвете команды (≈58 px, объёмный радиальный градиент от цвета команды), под ним название команды (18 px / 550) и очки команды в матче на сейчас («6 очков», склонение через `plural`) из `standings`. По центру — «VS» мелкими прописными.
- Под противостоянием, по центру, — чип: при трёх командах «Отдыхают Жёлтые» с точкой цвета. При двух командах в первой игре — «С мячом начинают Синие» (см. раздел 2); в следующих играх двух команд чипа нет.
- Действия (если `canRecord`): «Внести результат» (primary) и круглая «⋯» рядом — как сейчас, через `MatchAction`. Для тех, у кого нет прав записи, кнопок нет.

**Таблица — `material-graphite`.** Колонки как сейчас: Команда, И, В–Н–П, Мячи (с разницей мелко под счётом), О. Никакой подсветки строки лидера и никаких боковых отступов у строк: все строки выровнены по внутреннему отступу карточки. Разделители строк — тонкие линии.

**Последние игры — `material-graphite`.** Заголовок и «Все N →» справа (открывает существующую шторку истории). Каждая игра:
- строка «Игра N» слева, «Изменить» справа (если `canEdit`);
- строка счёта: команда слева, счёт в «пилюле» по центру, команда справа; победитель жирным, проигравший приглушённым, при ничьей обе обычные;
- **авторы голов в две колонки под своими командами**: левая команда — слева (выравнивание влево), правая — справа (выравнивание вправо), по одному автору в строке. «Алихан ×2» для нескольких голов одного автора. Если команда не забила — «—» приглушённо. Неизвестные авторы — как сейчас («автор не указан: N»), в колонке своей команды;
- **ассистент в скобках после автора**: «Алихан (Дамир)». При «×2» с разными ассистентами — отдельные строки на каждый гол (то есть группировка «×N» применяется только к подряд идущим голам одного автора с одинаковым ассистентом или без него).

Та же разметка строки игры используется в шторке «Все игры».

**Бомбардиры — `material-graphite`.** Место, имя, под именем точка и название команды (и «· гость»), голы справа крупно. Первое место — золотой кружок-медаль с цифрой, остальные — нейтральный кружок. Ассисты в эту карточку не добавляются (решение — моё, чтобы карточка не превращалась в таблицу; ассисты видны в истории и профиле).

### После завершения и до старта

- Пустые состояния «Протокол не вёлся» и «Матч ещё не начался» — без изменений.
- Завершённый матч: вместо карточки текущей игры остаётся заголовок «Итоги матча» и «Сыграно игр: N»; ниже те же три графитовые карточки. Оформление заголовка — на усмотрение исполнителя в рамках системы (без нового материала).

### Скелетон

`EventTabSkeleton` для `games` перерисовывается под новую раскладку (синяя карточка + три графитовые), правило DESIGN.md «скелетон копирует экран» и проверка `tests/ui/skeletons.spec.ts` действуют.

## 2. Жеребьёвка монетой

### Когда

Монета — второй шаг шторки «Начинаем матч», которая открывается кнопкой «Начать матч» во вкладке «Составы» (см. 3.6). Отдельной шторки подтверждения больше нет.

### Вопрос зависит от числа команд

| | 3 команды | 2 команды |
|---|---|---|
| Заголовок шага | Кто отдыхает первым? | Кто начинает с мячом? |
| Подпись | Монета выберет команду, которая пропускает первую игру. | Монета выберет команду, которая первой разыгрывает мяч с центра. |
| Ответ после приземления (крупно, 20 px / 600) | Отдыхают Жёлтые | С мячом начинают Синие |
| Под ответом | синяя плашка «Красные · ИГРА 1 · Синие» | та же плашка |

Сначала ответ на вопрос, потом следствие (пара первой игры). Ниже — кнопка «К игре 1» (primary), закрывающая шторку и открывающая вкладку «Игры», и подпись «Результат сохранён и виден всем участникам». (Текст кнопки — моё решение; в мокапе было «Начать игру 1», но матч к этому моменту уже начат.)

### Как выглядит монета

Стилизация под биметаллическую монету 200 тенге (образец 2020 года):
- серебряное внешнее кольцо и золотой центр (центр ≈ 70 % диаметра — пропорция 18,3 / 26 мм); какая часть какого цвета — по памяти, если у реальной монеты наоборот, поменять местами;
- ребро толщиной ≈ 7 px с 16 углублениями (видно в полёте, когда монета встаёт ребром);
- в золотом центре — горизонтальная штриховка (как фон цифры «200»), эмалевая точка в цвете команды и название команды прописными, «тиснёное» тенями;
- по кольцу по кругу — «FC ALTYNKA • 2026 • FC ALTYNKA • 2026 •», межбуквенный интервал рассчитывается так, чтобы текст заполнил окружность без разрыва на стыке;
- без герба и без «QAZAQSTAN».

Размер в шторке ≈ 150–170 px. Под монетой — «↑ Подбрось монету» с лёгким покачиванием стрелки; монета в покое слегка «парит».

### Как бросается

- Бросок — тап по монете или свайп вверх (сильнее свайп — выше и дольше полёт). С клавиатуры — Enter/Пробел на монете (это кнопка с понятной подписью).
- Полёт: подъём по параболе с приближением (масштаб растёт к вершине), вращение вокруг горизонтальной оси, тень на «полу» сжимается и бледнеет. Каждые пол-оборота видна следующая команда по кругу. Вращение быстрое в начале и замедляется к приземлению. Приземление — короткое сплющивание и отскок, мягкая вспышка.
- Хаптика Telegram (`lib/tg.ts`): лёгкий тик на каждую смену стороны, сильный — при приземлении.

### Откуда результат

- **Бросок и есть старт матча.** Тап отправляет существующий `POST /api/events/:id/games/start` (с тем же `requestId`/повтором, что сейчас). Монета взлетает сразу и крутится, пока не придёт ответ (не меньше ≈ 1,5 с полёта), затем приземляется на сторону из ответа: при трёх командах — отдыхающая команда (`restingTeamIndex`), при двух — команда с мячом.
- **Новое на сервере для двух команд:** при старте сервер случайно выбирает команду, начинающую с мячом, и сохраняет её в состоянии игры (например `kickoffTeamIndex` в `GameState`), отдаёт в `GameProtocolDto`. Для трёх команд не нужно. Старые протоколы без этого поля — чипа нет.
- **Ошибка старта:** монета возвращается в исходное положение без результата, под ней — текст ошибки (существующие формулировки: 409 «Составы изменились…», иначе «Не получилось начать матч. Попробуй ещё раз.») и бросок снова доступен с тем же `requestId`.
- **Повторного броска нет.** После приземления монета неактивна. Если шторку закрыть до ответа — старт всё равно мог пройти; при следующем открытии вкладки состояние берётся с сервера.
- **Другие участники** анимацию не видят: у них просто появляется вкладка «Игры» с чипом отдыхающей / начинающей команды.

### Уменьшение движения

`prefers-reduced-motion`: без полёта и покачивания; после ответа сервера монета сразу показывает нужную сторону, ответ появляется без сдвига.

## 3. «Составы» — редактор организатора

Порядок сверху вниз: карточка баланса → карточки команд → фиксированная панель действий над доком.

### 3.1 Карточка баланса — `material-blue`

- Переключатель «2 команды / 3 команды» во всю ширину (две равные кнопки, текст не переносится).
- Полоса на команду: точка + название, дорожка с заполнением в цвете команды (длина по среднему рейтингу на фиксированной шкале), среднее справа («6,4»). Анимация ширины при изменениях.
- Строка «Разница средних — 0,0». Без чипов «Ровно» / «Перекос».
- Кнопка «Перемешать» во всю ширину карточки, высота 48 px, вторичный стиль для цветного материала (полупрозрачная светлая заливка, как вторичные кнопки на карточках задач, `#babcec24` + `--rim`). Иконка shuffle.

### 3.2 Поведение «Перемешать» и смены числа команд

- Сразу, без шторки подтверждения: новый вариант через существующие `alternativeSplit` / `balanceTeams`. Тост «Новый вариант готов» с «Отменить» (существующий ToastProvider, 8 с).
- Смена 2 ↔ 3 так же мгновенно пересобирает команды, тост с отменой.
- Анимация иконки: вертикальное отражение (scaleY 1 → −1 с лёгким сжатием и перелётом, ≈ 460 мс); глиф shuffle симметричен сверху вниз, поэтому иконка не «отскакивает» обратно — следующее нажатие отражает в другую сторону. Игроки в карточках появляются короткой каскадной анимацией. Reduced motion — без анимаций.

### 3.3 Карточки команд — `material-graphite`

- Шапка: иконка футболки в цвете команды, название (заголовок карточки), под ним «6 игроков · 6,4». Справа чип «Форма» с точкой цвета. Без цветной полосы сверху карточки.
- Строки игроков отсортированы по рейтингу: имя, метки «ты» / «гость», рейтинг справа с цветом уровня (как кольцо рейтинга: 4–7 жёлтый, 8–9 оранжевый и т. д.). Прямые разделители между строками.
- Уровень гостя: тап по рейтингу гостя открывает выбор уровня 1–10 (вместо встроенного select в строке) — моё решение, исполнитель выбирает форму (маленькая шторка или поповер).
- Профиль игрока из редактора не открывается: тап по строке занят обменом (моё решение; профили открываются из «Участников» и из вида игрока). Требование DESIGN.md про 44 px ссылки профиля в редакторе снимается.

### 3.4 Обмен двумя тапами

- Тап по игроку — он выбран: мягкая заливка `--accent-soft`, **без обводки**. Остальные игроки его команды приглушаются (≈ 45 % непрозрачности), в строках других команд появляется маленькая иконка обмена.
- Панель действий превращается в одну строку: иконка обмена, «Обмен: **Имя**» (длинное имя обрезается многоточием), справа компактная кнопка «Отмена».
- Тап по игроку другой команды — обмен; обе строки коротко вспыхивают, тост «Асет и Олжас поменялись» с «Отменить». Тап по тому же игроку — снять выбор; по другому игроку той же команды — перенести выбор.
- Доступность: строки — кнопки с `aria-pressed`; Escape снимает выбор; изменения объявляются через существующий живой регион тостов.
- Шторка «Обменять игрока» и кнопки «Обменять» в строках удаляются.

### 3.5 Цвет формы

- Чип «Форма» открывает существующую шторку цветов (`TeamColorSheet`), но для одной команды: заголовок «Форма: Красные», пояснение «Выбери цвет манишек или формы на поле. Если цвет уже занят, команды поменяются цветами — игроки останутся на местах.», сетка 3 × 2 из шести футболок с подписями (Красный, Синий, Жёлтый, Зелёный, Белый, Чёрный). Текущий цвет — обводка акцентом и подпись «сейчас»; занятый другой командой — подпись «у Синих».
- Выбор применяется сразу и закрывает шторку (без кнопки «Применить»). Свободный цвет — команда переименовывается («Теперь Зелёные»); занятый — команды меняются цветами («Синие и Красные поменялись цветами»). Тост с «Отменить».
- Правила ревизии цветов и конфликтов из DESIGN.md остаются (шторка помнит ревизию, на конфликте — существующая ошибка).
- После старта матча меняются только цвета (как сейчас) — тем же чипом.

### 3.6 Панель действий и шторка старта

- Фиксированная панель над доком (через `MatchAction`): строка статуса с точкой и главная кнопка; слева от главной кнопки — круглая «Отменить» (иконка), когда есть что отменять.
  - черновик: «Черновик — видишь только ты» (или «Есть неопубликованные изменения» после публикации) + «Опубликовать составы»;
  - опубликованы и можно стартовать (`canStart`): «Опубликованы — видят все» + «Начать матч».
- «Начать матч» открывает шторку «Начинаем матч» (общий `ActionSheet`) из двух шагов:
  1. «Сверь цвета на поле» — «Манишки должны совпадать с командами в приложении.», чипы «● Красные 6 / ● Синие 6 / ● Жёлтые 6»; чипы нажимаются и открывают шторку цвета своей команды (см. «Цвета до старта» ниже);
  2. вопрос монеты по числу команд (раздел 2) и сама монета. Подпись: «Подбрось монету — матч начнётся, составы зафиксируются.»
- **Опубликованы, но стартовать нельзя** (`canStart` ложен: матч не сегодня, не назначен, состав устарел): в панели только строка статуса «Опубликованы — видят все» и под ней приглушённо «Начать матч можно в день игры» (если дело в дате), без главной кнопки. Если панель заблокирована (`actionBlocked`), её содержимое рендерится в потоке страницы, как сейчас.
- **Цвета до старта.** Чип «Форма» в карточке меняет цвет в черновике (как сейчас: применяется к черновику сразу, публикуется вместе с составами). В шторке «Начинаем матч» чипы цветов на шаге 1 нажимаются: каждый открывает ту же шторку цвета для своей команды, но выбор там **сразу сохраняется** на сервер (`PATCH /teams/colors` с ревизией, как после старта) — публикация не сбрасывается, черновик остаётся «без изменений», бросок монеты доступен. Конфликт ревизии — существующая ошибка в шторке. Режим шторки цветов «все команды сразу» удаляется — везде одна команда.
- Предупреждения «Состав изменился — пересобери команды» и «Составы на сервере изменились…» остаются, над карточкой баланса.
- Пока нет распределения: карточка баланса показывает переключатель и главную кнопку «Разделить на команды» вместо полос (поведение «первого распределения» как сейчас, оформление — на усмотрение исполнителя).

## 4. «Составы» — вид игрока

- Те же графитовые карточки команд, без карточки баланса, «Перемешать», «Форма», обмена и рейтингов (средние рейтинги — только для организатора, как сейчас).
- Своя команда первой, в её шапке — метка «Твоя команда». Отдельная карточка «Твоя команда — …» удаляется.
- Имена открывают спортивный профиль (как сейчас).
- До публикации — существующее пустое состояние «Составы ещё не опубликованы». После старта — тихая пометка «Матч идёт» над карточками; карточки те же.

## 5. Ассисты

### Ввод — шторка результата игры

- Легенда блока: «Голы и пасы», справа «N из M авторов». Подсказка: «Пас необязателен — его можно указать позже.»
- Карточка гола получает вторую строку под автором, отделённую пунктиром: «↳ Пас: выбрать» и «+» справа; после выбора — «↳ Пас: **Дамир**» и «Изменить», или «↳ Без паса».
- Строка паса появляется только когда автор гола известен (моё решение: пас к неизвестному автору бессмыслен для истории).
- Список паса раскрывается под карточкой так же, как выбор автора: только игроки той же команды, **без самого автора**, гости с «· гость», последняя опция «Без паса». Escape закрывает, фокус возвращается.
- Смена автора гола сбрасывает пас, если ассистент стал автором.
- Подпись под кнопкой сохранения: «Автора и пас можно указать позже».
- Черновик результата (`lib/gameDraft.ts`) сохраняет пасы вместе с голами; восстановление и повтор отправки с тем же `requestId` работают как сейчас.

### Хранение

- Пасы — данные конкретного гола, а не суммы на игрока. Сейчас игра хранит `scorers: {signupId, goals}[]` (суммы), а порядок карточек живёт только на клиенте (`GoalRuns`). Нужен упорядоченный список голов на каждую сторону (`автор | null`, `ассистент | null`); `scorers` для таблицы, бомбардиров, достижений и статистики выводится из него, чтобы остальной код не менялся.
- Состояние игры хранится JSON в `events.game_state_json`, поэтому новая таблица/колонка не нужна; форма JSON и zod-схема `api/games.ts` расширяются совместимо. Старые игры без списка голов читаются как сейчас и пасов не имеют. Конкретную форму данных выбирает исполнитель.
- Сервер проверяет: ассистент из той же команды, что и автор; ассистент ≠ автор; у гола без автора нет ассистента; количество голов не больше счёта (как сейчас).
- Отпечаток команды (`fingerprint` в `domain/games.ts`) учитывает пасы, чтобы повтор с другими пасами не считался дублем.

### Показ

- «Последние игры» и шторка «Все игры»: «Алихан (Дамир)» — ассистент в скобках, приглушённым цветом (см. раздел 1).
- Профиль (`PlayerSports`): ячейка «Ассисты» показывает реальную сумму пасов игрока по сохранённым идентичностям протокола (тот же принцип, что для голов в `playerStatistics.ts`); «—» остаётся только пока у игрока нет ни одной игры с записанными пасами — точное правило «— или 0» на усмотрение исполнителя, без выдуманных нулей для старых матчей.

## Ограничения

- Весь новый текст интерфейса — на русском, словарь DESIGN.md: «Матч» — всё событие, «Игра N» — короткая игра.

- Светлая тема: все новые элементы получают переопределения в `themes.css` (материалы остаются цветными, как сейчас). Монета одинакова в обеих темах.

- Без новых зависимостей; анимации — CSS / Web Animations / rAF.
- Миграций D1 не требуется (если исполнитель не решит иначе — тогда правило «миграция до деплоя» из CLAUDE.md).
