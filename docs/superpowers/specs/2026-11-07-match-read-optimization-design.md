# Оптимизация чтения матча

Пользователь согласовал оптимизацию после разбора CPU-профиля и повторных SQL-чтений.
Цель — уменьшить CPU и объём обработки D1 при GET детали матча, сохранив ответ,
права доступа и свежесть между HTTP-запросами.

Выбранный подход: явно передавать уже загруженные данные внутри одного чтения.
Функции формирования составов и игрового протокола принимают готовую запись матча;
очередь использует известный лимит, протокол переиспользует готовые очередь/составы.
Оплата принимает уже найденный счёт, удаляется неиспользуемое чтение матча.
Пользователи участников переиспользуются для рейтингов и оплаты; отсутствующие
получатели/должники дочитываются. Самостоятельные вызовы существующих функций работают.

Общий кэш между запросами не используется: он требует инвалидации после изменений.
Переписывание всего ORM на SQL не требуется для удаления подтверждённых дублей.

Ограничения: без миграций, зависимостей, изменений UI, авторизации и тарифов.
Деплой не входит в этот запрос. Не обещать 10 мс без проверки production после выпуска.
Проверки: SQL-бюджет и один полный SELECT events на деталь, эквивалентность DTO,
свежесть после изменения данных, роли, legacy/ручной старт, отсутствующие данные,
реальные runtime-тесты Worker, typecheck и повторный замер на локальном снимке.
