# Поздние награды и результативность в опросе — 22 ноября 2026

## Зачем

16 ноября прод перезаписали версией из `origin/main` без наград матча. В опросе по матчу 12 (22 ноября)
шага наград не было: 14 из 17 участников уже отправили оценки, наград ноль. Нужно, чтобы награды
появились снова, чтобы уже ответившие тоже могли выбрать лучших, и чтобы при оценке было видно, что
игрок сделал за игру.

## Цели

1. Слить `origin/main` (PR #18–#23) с локальными наградами и опубликовать одну версию со всем сразу.
2. Те, кто отправил оценки без наград, пока опрос открыт, могут один раз пройти только шаги наград.
3. В шаге оценки игрока и в выборе награды видны голы, пасы, игры и результат игрока за матч.
4. Автозакрытие «ответили все» ждёт шага наград: участник считается ответившим, когда отправил оценки
   (или пропустил опрос) и либо выбрал награды, либо пропустил их.
5. Один раз отправить личное сообщение тем, кто ответил без наград по матчу 12, с кнопкой в опрос.
   Точный текст утверждает пользователь до отправки.

## Не цели

- Менять уже отправленные оценки игроков.
- Повторный выбор наград после отправки.
- Награды для уже закрытых опросов.

## Подходы

- **Отдельная отправка наград (выбран).** `POST /events/:id/review/awards` дописывает `awards` в
  сохранённый ответ и вставляет строки `award_votes` в одном пакете; пропуск записывается как
  `awardsSkipped: true`. Уже существующие оценки и триггер не трогаются.
- Разрешить пересылать весь ответ заново. Ломает «после отправки изменить нельзя» и голоса по триггеру.
- Хранить поздние награды в отдельной таблице. Лишняя схема ради одного случая.

## Как устроено

- `ReviewInput` получает необязательное `awardsSkipped`. Ответ «без наград» — это ответ без `awards`
  и без `awardsSkipped`, не пропуск опроса.
- `MatchReviewDto` получает `canAddAwards` (опрос открыт, ответ отправлен не пропуском, наград нет и
  не пропущены). Экран «Спасибо» показывает карточку «Выбери лучших игроков матча»; она открывает
  `ReviewRater` в режиме только наград.
- Участники опроса получают `stats` из протокола игр (`summarizePlayerProtocol`): игры, голы, пасы,
  победы/ничьи/поражения, `assistsTracked`. Без записанных игр `stats` нет и строка не показывается.
- `closeReview(onlyComplete)` считает ответившим участника с ответом, у которого есть `awards`,
  `awardsSkipped` или `skipped`. Подсчёт «Ответили N из M» для организатора тот же.
- Уведомление — разовый скрипт/команда по матчу 12 через личные сообщения бота, тем, у кого
  `canAddAwards`. Сначала пробный прогон со списком получателей и текстом.

## Решения исполнителя

Формат строки статистики, подписи и тексты — в духе существующего опроса и правил DESIGN.md.
