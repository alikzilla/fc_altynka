# Церемония награждения — 23 ноября 2026

Статус: на согласовании.

## Зачем

Награды матча (MVP и лучшие по позициям, см. `2026-11-15-match-awards-design.md`) сейчас выглядят как
строка текста в ленте и таблица на странице матча. Владелец хочет, чтобы победа ощущалась праздником:
каждого победителя представить отдельно и своими словами, а самим победителям сообщить лично.

## Цели

1. Новый вид поста в ленте **«Церемония»**: один пост на матч, внутри листаются карточки победителей, по
   одной на каждую присуждённую награду. В карточке фото, награда, титул, оригинальный текст, цифры за
   матч и число голосов.
2. **Личное поздравление** в Telegram каждому победителю любой из пяти наград.
3. **Корона действующего MVP** на аватаре (моё предложение, владелец не возразил).
4. **Блок «Награды матча» на странице матча** из карточек с фото вместо таблицы (моё предложение).

## Не цели

- Менять правила голосования и подсчёта (`awardWinners` остаётся единственным источником победителей).
- Переделывать уже опубликованные посты `awards`: они остаются в ленте текстом, как сейчас.
- Писать о наградах в групповой чат.
- Картинки, сгенерированные на сервере (карточка рисуется в мини-аппе).

## Чего нельзя допустить

- Разных победителей в ленте, поздравлении, короне и на странице матча.
- Раскрытия того, кто за кого голосовал: наружу выходит только число голосов победителя, как сейчас.
- Поздравления до закрытия опроса или дважды одному человеку за один матч.
- Горизонтального скролла страницы из-за карусели (`tests/ui/fixtures.ts`).
- Текстов, которые ломают правила ленты: имя только в именительном падеже, о человеке — в настоящем
  времени или без глагола (пол неизвестен), по имени только хвалим.

## Подходы (выбран 1)

1. **Новый вид поста `ceremony` с данными карточек в `feed_posts.payload_json` (выбран).** Пост пишется
   один раз при закрытии голосования, тексты и цифры фиксируются, имя и фото подставляются при чтении.
   Лента читается так же быстро, данные переиспользуются в поздравлении.
2. Собирать карточки при каждом чтении ленты без миграции. Лишние запросы на каждое открытие главной;
   правка шаблонов меняет тексты старых постов.
3. Отдельная строка `feed_posts` на победителя, клиент склеивает в карусель. Свои реакции на каждого, но
   ломаются «Показать ещё», удаление поста администратором и предпросмотр из пяти постов.

В ленте владелец выбрал один пост с каруселью, а не отдельный пост на каждого победителя: пять постов
подряд заняли бы весь предпросмотр.

## Устройство

### Общая логика (`packages/core/src/ceremony.ts`)

- `FEED_KINDS` получает `'ceremony'`.
- Тип карточки, который хранится и уходит в API:

  ```ts
  interface CeremonyCard {
    award: AwardKey; userId: number;
    title: string;          // титул: «Гроза ворот»
    text: string;           // текст карточки
    votes: number;
    stats: { goals: number; assists: number | null; games: number; wins: number } | null; // null без протокола игр
    sharedWith: number[];   // другие победители той же награды
  }
  ```

- `composeCeremonyPost({ eventId, date, cards: { award, userId, name, votes, stats, sharedWith }[], recent })`
  возвращает `FeedDraft` с `payload` (массив `CeremonyCard` без имён) и общий текст поста. Порядок карточек:
  по `AWARDS`, внутри награды по `userId`.
- Выбор формулировок через существующий `Voice`: зависит от матча, пропускает недавно использованные в
  группе. Слоты `ceremony:<award>:<userId>`, чтобы у двух карточек одного поста не совпадали фразы.
- `FeedPostDto.ceremony?: (CeremonyCard & { name: string; photoUrl: string | null })[]`.
- Строка цифр собирается на клиенте из `stats`, в тексте шаблона цифры подставлены при записи.

### Тексты

Подстановки: `А` — имя победителя, `{д}` — «22 ноября», `{голоса}` — «6 голосов», `{голы}` — «3 гола»,
`{пасы}` — «2 паса», `{г+п}` — «3 гола и 2 паса» (нулевая часть опускается: «3 паса»), `{победы}` — «4 победы». Шаблоны «с цифрами»
используются, только когда выполнено условие; иначе берутся общие.

**Титулы** (один на карточку, тоже через `Voice`):

| Награда | Титулы |
|---|---|
| MVP | Главный герой вечера · Человек матча · Лицо вечера |
| Нападающий | Гроза ворот · Острие атаки · Снайпер вечера |
| Полузащитник | Мозг команды · Дирижёр · Мотор центра поля |
| Защитник | Стена · Замок обороны · Надёжный тыл |
| Вратарь | Последний рубеж · Надёжные руки · Хозяин штрафной |

**MVP матча**
- А — MVP матча {д}. Партнёры отдали голоса, и спорить тут не о чем.
- Лучший игрок вечера по версии тех, кто был на поле: А.
- Есть игроки, вокруг которых крутится весь матч. {д} это А.
- А забирает главный приз вечера. {голоса}, и все заслуженные.
- Если пересказывать матч {д} одним именем, это имя — А.
- Новый обладатель короны: А. Она остаётся у хозяина до следующего MVP.
- С цифрами (голы + пасы ≥ 3): {г+п} за вечер. А делает матч {д} своим и забирает MVP.
- С цифрами (голы + пасы ≥ 3): Цифры и голоса совпали: {голы}, {пасы} и звание MVP. Это А. (нулевые цифры опускаются)

**Лучший нападающий**
- Защитники ещё долго будут вспоминать этот вечер. Лучший нападающий матча {д}: А.
- А — самый опасный человек у чужих ворот.
- Каждый выход один на один — как приговор. Лучший нападающий: А.
- Острие атаки матча {д}: А.
- Вратари соперников выдыхают: матч позади. Лучший нападающий вечера — А.
- С цифрами (голы ≥ 2): А — {голы} за вечер и лучший нападающий матча {д}.
- С цифрами (голы ≥ 2): {голы} на счету и награда лучшего нападающего. А в форме.

**Лучший полузащитник**
- Все атаки начинаются с одного человека. Лучший полузащитник матча {д}: А.
- В центре поля в этот вечер хозяин один: А.
- Пас, отбор, снова пас. А — лучший полузащитник вечера.
- Связующее звено матча {д}: А.
- Голы забивают другие, а матч строит А.
- С цифрами (пасы ≥ 2): {пасы}, и каждый как подарок. А — лучший полузащитник матча.
- С цифрами (пасы ≥ 2): А раздаёт {пасы} за вечер. Лучший в центре поля.

**Лучший защитник**
- Через эту зону в этот вечер не пройти. Лучший защитник матча {д}: А.
- А — стена, о которую разбиваются атаки.
- Нападающие соперников ищут обход, а там снова А.
- Надёжнее обороны в этот вечер не было. Лучший защитник: А.
- Тихая, незаметная, бесценная работа. Лучший защитник матча {д}: А.
- С цифрами (победы ≥ 2): {победы}, и в каждой надёжный тыл. А — лучший защитник вечера.

**Лучший вратарь**
- Последний рубеж держится. Лучший вратарь матча {д}: А.
- А — руки, которым партнёры доверяют больше всего.
- Чтобы забить, надо было пройти не только защиту. Ещё и А.
- Нападающие соперников запомнят этот вечер: в воротах стоит А.
- Лучший вратарь вечера по голосам партнёров: А.
- С цифрами (победы ≥ 2): {победы} за вечер, и за каждой стоят надёжные руки. Лучший вратарь: А.

**Подписи на карточке** (не часть текста):
- Награда делится: «Награда на двоих · А и Б» («на троих» и т. д.; больше трёх — «Награду делят N игроков»).
- У игрока две награды и больше: чип «2 награды за вечер».

**Общий текст поста** (виден над каруселью, используется в листе удаления и как запасной текст):
- Награды матча {д} вручены. MVP — А.
- Голосование закрыто, у матча {д} есть свои герои.
- Церемония награждения матча {д}. Листай карточки.
- Партнёры выбрали лучших в матче {д}.

Без присуждённого MVP варианты с «MVP — А» не используются.

### База и лента (`apps/worker`)

- Миграция `0019_feed_payload.sql`: `ALTER TABLE feed_posts ADD COLUMN payload_json TEXT`. В `db/schema.ts`
  поле `payloadJson`. Применить к удалённой D1 до выката Worker.
- `publishAwards` пишет пост `ceremony` вместо `awards`: те же `awardsByEvent`, плюс статистика игроков за
  матч через `summarizePlayerProtocol` по сохранённому протоколу (нет протокола — `stats: null`).
- `awardsToPublish` не берёт матчи, где уже есть пост `awards` **или** `ceremony`.
- Пост `ceremony` с MVP стоит на месте `AWARDS_WITH_MVP` и, как сейчас, заменяет `top_rated`; условие в
  `publishClosedVotes` проверяет оба вида.
- `userId` поста — MVP, если он один (строка автора с его фото), иначе `null`.
- Чтение ленты добавляет к посту `ceremony` имена и фото из `users`/`match_participants`.
- Исправление результата матча (переписывание постов) пост `ceremony` не трогает: он пишется по закрытию
  голосования, как `awards` сейчас.

### Личное поздравление

- Источник — `AutomaticNotifications` в DO матча, как приглашение в опрос. Ключ задачи
  `award:<closesAt>:<tgId>`, одна задача на человека за матч, даже если наград несколько.
- Время: `nextDeliveryTime(closesAt)` (тихие часы Алматы). Позже `closesAt + 24 ч` не отправляется.
- До закрытия опроса победители не считаются: задача только будит DO к `closesAt`, а текст собирается
  при отправке через `awardsByEvent`.
- **Досрочное закрытие** (`closeReview`) сейчас DO не будит. Нужно после успешного закрытия вызвать
  `sync.request` (флаг, который ставит DO на пересчёт задач), иначе поздравление придёт только через 72 часа.
- Получатель: победитель с аккаунтом. Фильтры (уведомления включены, личка доступна, участник группы)
  обычные, из `PersonalDelivery`.

Текст (`render/personal.ts`, `personalAwards`):

```
<название группы>

<b>🏆 MVP матча — это ты · 22 ноября</b>
Партнёры назвали тебя лучшим игроком матча. Корона твоя до следующего MVP.
За тебя проголосовали 6 партнёров.
За матч: 3 гола, 2 паса, 4 победы в 5 играх.

Это твоя 3-я награда MVP. До серебра — ещё 2.
[Посмотреть награды]
```

- Заголовок: одна награда — «MVP матча — это ты», «Лучший нападающий матча — ты» и т. д. (название
  награды как ярлык, к человеку прилагательное не относим). Несколько наград — «Две награды за матч» /
  «Три награды за матч», ниже список «MVP матча — 6 голосов».
- Первая строка по главной награде (MVP первым), вариант через хеш матча и человека:
  - MVP: «Партнёры назвали тебя лучшим игроком матча. Корона твоя до следующего MVP.» · «Главная награда
    вечера достаётся тебе. Заслуженно.» · «Лучший игрок матча по голосам тех, кто был рядом на поле, — это ты.»
  - Нападающий: «Самый опасный у чужих ворот, по мнению партнёров, — ты.» · «Вратари соперников, кажется,
    уже в курсе.»
  - Полузащитник: «Центр поля в этот вечер был твоим.» · «Партнёры отметили, как ты ведёшь игру.»
  - Защитник: «Через тебя в этот вечер было не пройти.» · «Самый надёжный тыл вечера — твой.»
  - Вратарь: «Спасибо надёжным рукам: партнёры это заметили.» · «Последний рубеж держался благодаря тебе.»
- Общая награда: «Награда на двоих: ты и Б.»
- Строка цифр — только если есть протокол игр; пасы — только если их записывали.
- Строка прогресса по лестнице «MVP» или «Лучший на позиции» (`playerAchievements`, награды считаются
  во всех группах игрока, как в профиле): новый уровень — «Новый уровень: «MVP», серебро.»; иначе
  «Это твоя N-я награда MVP. До <следующий уровень> — ещё K.»; на последнем уровне — без «до».
- Кнопка «Посмотреть награды» ведёт на страницу матча (`miniAppLink(env, 'e<id>')`).

### Корона действующего MVP

- **Хозяин короны в группе**: победитель(и) MVP последнего по `closes_at` закрытого и не отменённого
  матча группы, где MVP присуждён. Корона переходит к следующему MVP, а если в новых матчах MVP не
  присуждали, остаётся у прежнего хозяина.
- Одна функция `reigningMvps(db, communityIds, now): Map<communityId, userId[]>` в `domain/awards.ts`.
  Просмотр назад ограничен (например, 10 последних закрытых матчей группы), чтобы не считать всю историю.
- Флаг `reigningMvp` рядом с `injured` там, где `injured` уже есть: список игроков, состав матча, профиль
  (в профиле — если корона есть хотя бы в одной общей со зрителем группе, как с травмой).
- Значок: маленькая золотая корона в правом верхнем углу аватара (травма в левом верхнем). У скринридера
  «Действующий MVP». В профиле под аватаром добавляется чип «Действующий MVP».

## Проверка

- Core: `composeCeremonyPost` — порядок карточек, шаблоны с цифрами только при условии, разные фразы у
  карточек одного поста, нет «MVP — А» без MVP, общая награда, две награды у одного игрока. Проверка,
  что в шаблонах нет глаголов прошедшего времени мужского рода (по списку окончаний, как в тестах ленты,
  если такая проверка уже есть).
- Worker: миграция; пост `ceremony` при чтении ленты после закрытия, не дублируется, заменяет `top_rated`;
  матч со старым постом `awards` не получает второй; `payload` и имена с фото в DTO; поздравление
  уходит после закрытия и только победителям, одно на матч при нескольких наградах, не уходит позже 24 ч,
