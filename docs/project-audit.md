# FC Altynka: разбор проекта и обновление UI

Дата: 4 ноября 2026. Изменения подготовлены локально, без деплоя.

Последующая визуальная итерация по запросу пользователя: [Apple Liquid Glass, сине-голубая тема и floating dock](liquid-glass-review.md). Текущие токены находятся в `DESIGN.md` и исходном CSS; ниже сохранён разбор архитектуры и первого этапа работ.

## Архитектура

Монорепозиторий pnpm: React 19 + Vite + Wouter в `apps/miniapp`, Hono + grammY в `apps/worker`, общая чистая логика в `packages/core`. Worker обслуживает API, вебхук и статические файлы миниапки. D1 хранит данные через Drizzle; Durable Object EventSync синхронизирует сообщения Telegram. Аутентификация API использует подписанный Telegram initData. Есть разделение ролей: игрок, организатор и администратор.

Главные сценарии уже реализованы: запись, резерв, гости, назначение времени и поля, балансировка и публикация команд, разделение расходов, отметка оплаты и напоминания. Серверные правила и API-контракты при обновлении интерфейса сохранены.

## Что изменилось

- Главная выделяет активный сбор: дата, время, поле, заполнение списка, личный статус и переход к деталям. Архив стал компактным; админская кнопка создания не вытесняет ближайшую игру.
- Общие компоненты: навигация с SVG-иконками, инициалы игроков, заголовки с доступным переходом назад, состояния загрузки и пустого списка, ошибки с повторной попыткой.
- Экран сбора разделяет время и поле, показывает статус записи. Вкладки поддерживают стрелки, Home/End, управление фокусом и связи tab/tabpanel. Неизвестная вкладка возвращает к списку.
- В формах видны процессы сохранения; повторные действия блокируются. В профиле ошибки связаны с полями. В редакторе команд перенос через заголовок доступен с клавиатуры.
- В оплате используются иконки и текстовые статусы для скринридеров; ошибка копирования больше не показывается как успех.
- `useResource` сохраняет данные при повторной загрузке текущего ресурса, но скрывает их при смене маршрута и игнорирует запоздалые ответы. Это предотвращает показ действий предыдущего сбора на новом маршруте.
- Тема следует Telegram `colorScheme` и событию `themeChanged`, с удалением обработчика при размонтировании. Отступы учитывают safe area устройства и интерфейса Telegram.
- Шрифт Onest размещается в сборке через Fontsource. Запросов к Google Fonts больше нет. Уважено `prefers-reduced-motion`, добавлены focus-visible и стили выделения текста.

## Подключённые инструменты

В локальной конфигурации Codex зарегистрированы:

| Имя | Реализация | Проверка |
| --- | --- | --- |
| `cloudflare` | официальный `https://mcp.cloudflare.com/mcp` | OAuth завершён успешно; доступ отдельных API из этой сессии не проверялся |
| `playwright` | официальный `@playwright/mcp`, headless | MCP handshake и каталог инструментов |
| `telegram-altynka` | `scripts/mcp/telegram.mjs`, официальный MCP SDK и Telegram Bot API | реальный бот и четыре диагностические команды |

Глобальная конфигурация не хранится в репозитории. Новые инструменты могут потребовать нового сеанса Codex. Сами изменения миниапки доступны сразу после запуска dev/build.

Telegram MCP предоставляет `get_bot`, `get_webhook`, `get_commands`, `get_menu_button`. Это диагностический коннектор только для чтения. Он не читает переписку и не потребляет обновления через getUpdates. Для изменения вебхука уже существует `apps/worker/scripts/set-webhook.sh`; запускать его нужно только когда требуется изменение реального бота.

Секреты читаются как данные через `parseEnv`: `.dev.vars`, затем `.webhook.env`, затем переменные процесса. Файлы не исполняются как shell-код. Токены не записаны в MCP-конфиг и скрываются в результатах; ошибки транспорта не передаются наружу, поскольку могут содержать секретный URL Telegram.

Официальные навыки `wrangler` и `workers-best-practices` установлены из `cloudflare/skills`. Для UI использованы существующие frontend-design, impeccable и vercel-react-best-practices. Установленные навыки будут доступны в следующем ходе/сеансе Codex.

## Состояние работающей интеграции

При проверке `fc_altynka_bot`: вебхук установлен, ожидающих обновлений 0, кнопка меню типа `web_app`, пользовательских команд в default scope 0. Публичный `/api/health` Worker отвечает HTTP 200 и `ok: true`.

Telegram хранит последнюю ошибку вебхука `500 Internal Server Error` от `2026-11-03T19:53:10Z` (4 ноября, 00:53 Алматы). Пустая очередь и health endpoint не доказывают исправность обработки каждого обновления. Причина исторической ошибки не установлена; для её воспроизведения и анализа нужен соответствующий запрос и серверный лог. Диагностика не отправляла сообщений и не изменяла вебхук.

В `wrangler.jsonc` явно не включены Workers Logs/Traces. Перед следующим продакшн-релизом стоит включить нужное наблюдение и проверить доставку вебхука на реальном сценарии. Конфигурация работающего Worker в этой задаче не менялась.

Cloudflare сообщает, что используемый `@cloudflare/vitest-pool-workers` переименован в `@cloudflare/vitest-plugin`. Текущие тесты работают; миграция тестового раннера оставлена отдельной задачей, чтобы не смешивать её с UI.

## Проверка

```bash
pnpm typecheck
pnpm test                  # core + miniapp + Worker
pnpm test:connectors       # MCP протокол, read-only методы, защита секретов
pnpm test:ui               # Chromium, локальные синтетические API-ответы
pnpm build
pnpm check:telegram        # только чтение реального бота и /api/health
```

Итоговый прогон: core — 24 теста, миниапка — 39, Worker — 95, MCP — 3, Playwright — 8. Всего 169 тестов прошли; проверка типов и production-сборка также успешны. Механический детектор Impeccable не нашёл нарушений.

Браузерный набор проверяет маршруты на 320/390/768/1440 px, отсутствие горизонтального переполнения, длинные имена/поле и редактор расходов на 320 px, работу вкладок с клавиатуры, ошибку сети и повторную попытку, пустой список, тёмную оплату, safe areas и скрытие админской навигации от игрока. Axe проверяет WCAG A/AA главного экрана на четырёх ширинах, остальных основных экранов на 390 px и тёмного экрана оплаты. Это автоматические проверки выбранных состояний, не сертификат соответствия WCAG всего продукта.

Скриншоты сохраняются в `artifacts/ui/` (gitignored). Данные в них синтетические, платежи и сообщения не отправляются. Проверены Chromium и эмуляция размеров; реальные Telegram WebView на iOS/Android, клавиатура устройства, тактильная отдача и переход в Kaspi на физическом устройстве не проверялись.
